Unavailable marker

Final treatment for a value the backend does not have. Direction A styling with B's hatched field, changed so it cannot be read as an input or a checkbox. All values below come from the mock fixtures.

In a record

The hatch fills the value slot from rule to rule. It has no border, fill or corner of its own, so it reads as part of the record's grid, like a box nobody filled in on a paper form. When adjacent fields are missing for one reason, the reason is given once under the group.

In a table

In a table the word sits where the number would, with the column's own alignment. When a block of cells is missing for one reason, the cells merge into one hatched span that states the reason, so the word is not repeated four times.

Beside real controls

What keeps it from reading as a control: inputs and checkboxes have a 3:1 border, a white fill, rounded corners, a fixed height and text set from the left. The marker has none of those. It has no edge of its own, takes the shape of the cell it sits in, keeps the column's alignment, and never changes on hover or focus.
